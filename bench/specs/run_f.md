あなたは Unity 2022.3 のエディタ拡張「かいへんナビ」（このリポジトリ、パッケージ Packages/com.suzuki-y0.jeni.kaihen-navi）の開発担当です。対象は VRChat 改変の初心者。日本語でコメントを書き、既存のコードスタイル（C# 7.3 相当、var、日本語 XML コメント）に合わせてください。まず HANDOFF.md と関係するコードを読んで全体を把握してください。

## 守るルール
- コードは Editor 専用。アップロードされるアバターに独自スクリプトを残さない（MA などの既存コンポーネントは可）。
- アバターや服・アクセの元アセットは書き換えない（必ず複製してから変更）。
- 新しいファイルを足したら `python3 tools/gen_meta.py` で .meta を作る。
- Unity はここでは動かせない。`bash tools/check.sh` でスタブを使ったコンパイル確認と翻訳チェックができるので、最後に必ず通すこと（スタブが足りなければ tools/stubs に最小限追加してよい）。
- 言語ファイル（Editor/Localization/*.json）に新しいキーを足すときは ja / en / zh-Hans / ko すべてに入れる。文言は初心者が読んで分かる言葉で。画面上の同じ機能の名前は、左ナビの名前（feature.ID.nav）とボタン名などでそろえる。
- UI は Editor/UI/KaihenNavi.uss の既存トークンとクラス（kn-*）を使い、今の VCC 風デザインに合わせる。Unity 標準の GenericMenu のような見た目のものを新しく足さない。
- **このツールで行う変更はすべて Ctrl+Z（Undo）で戻せること。** Undo.RegisterCreatedObjectUndo / Undo.RecordObject / Undo.AddComponent / Undo.DestroyObjectImmediate / Undo.SetTransformParent などを使い、1 つの操作は Undo.SetCurrentGroupName + CollapseUndoOperations で 1 手にまとめる。ウィンドウ側の自動保存やバックアップが Undo 履歴を壊さないか注意。
- git commit はしないこと（こちらでレビューしてコミットする）。最後に変更点と、Unity で確認が必要な点を日本語で短くまとめる。
## 担当：「髪の内側の色を変えたい」（インナーカラー）を、面ごとの判定に作り直す（Features/InnerColor*.cs）

ユーザー（作者）と相談して、判定ロジックを根本から変えることに決まった。

### これまでの方式と問題
画像（テクスチャ）の 1 点ずつ「外から見えるか」を GPU で測り、2nd カラーのマスクを塗っていた。
髪のテクスチャは、外側の面と内側の面で画像の同じ場所を共有していることが多く、画像の 1 点ずつでは分けられない。外側にまだらに色が出る。

### 新しい方式（試作で効果を確認済み）
1. **面（三角形）ごとに判定する。** 髪のメッシュを今の姿勢で BakeMesh し、各三角形のワールド法線 n と重心 p を求める。
   頭の中心 c = Head ボーン位置 + アバターの上方向 × (身長 × 0.04)。
   d = c - p から上下成分を 70% 弱めたベクトル（d -= up * dot(d, up) * 0.7）を正規化し、dot(n, d) > しきい値 なら「内側の面」。
   しきい値の初期値は 0.15。画面の「内側にする範囲」スライダーで 0.6〜-0.2 くらいを動かす（大きくすると範囲が広がる向きに）。
   「高さ」スライダー（0 = 全部、上げるほど毛先側だけ）：p の高さ（c からの上方向成分）が、その髪の最も低い点 × 係数 より低い面だけにする。
   対象は、選んだ髪の、選んだマテリアルのサブメッシュの三角形だけ。
   試作の結果：Cazalis の Hair_Back 2300/6378、Hair_Side 1064/3480、Hair_Tail 270/1188、Hair_Bang 309/5104 面が内側になり、正面から見ると内側の層だけにきれいに色が入り、後ろ・横から外側に色が漏れなかった。
2. **色の付け方：メッシュの複製に「内側用のサブメッシュ」を足し、内側用のマテリアルを当てる。** テクスチャは描かない。
   - 元のメッシュアセットは書き換えない。Object.Instantiate(sharedMesh) で複製（ブレンドシェイプ・ボーン・bindposes を保つ）し、内側の三角形を元のサブメッシュから外して、最後に 1 つサブメッシュを足してそこへ入れる。
   - 複製メッシュはアバターの作業フォルダ（WorkFolders）内に .asset で保存。同じ髪をやり直すときは、毎回「元のメッシュ」から作り直す（複製を重ねない）。元のメッシュの参照は状態（InnerColorState）に保存する。
   - 内側用のマテリアルは、元の髪マテリアルの複製。lilToon なら _MainTexHSVG の彩度を 0 にして元の濃淡だけ残し、_Color に選んだ色をかける（白っぽい髪でも、黒っぽい髪でも色が見えるよう、明るさの補正スライダー「色の明るさ」も用意）。lilToon 以外は _Color だけ。
   - レンダラーの sharedMesh と sharedMaterials の変更は Undo で戻せること（Undo.RecordObject）。プレビュー・調整・元に戻す、すべて Ctrl+Z 1 回で戻る。
   - 「元に戻す」で元のメッシュとマテリアルに戻し、作ったファイルは誰も使っていなければ消す（既存の後片付けの仕組みを流用）。
   - マテリアルの数が髪 1 つにつき 1 増えることを、画面に小さく注意書きする（VRChat のパフォーマンス表示に影響）。
3. 画面：既存の UI（髪の選択、色、プリセット色）を残し、「内側の決め方」の 3 択（内側の層 / 下のほう / 後ろの内側）は廃止して、「内側にする範囲」「高さ（毛先だけにする）」の 2 つのスライダーにする。スライダーを動かしたら少し待って自動で反映（今と同じ）。「プレビューする」ボタンは「反映する」でもよい（名前は分かりやすく）。
4. 不要になった GPU・テクスチャマスクの仕組み（InnerColorVisibility.cs / .shader、InnerColorOpenness.cs、InnerColorMask.cs の不要部分）と、それに対応するテスト・スタブは削除してよい。既存の状態ファイルに旧方式（2nd カラーとマスク画像）の記録がある場合は、「元に戻す」で旧方式の変更も戻せるように互換を残す。
5. tools/ に、三角形の判定（法線・頭の中心・しきい値・高さ）の単体テストを足す（check.sh から呼ぶ）。
